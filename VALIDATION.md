# Release 0.2.2 results

Validated on 7 September 2026 locally, with the final cloud events recorded on 8 September UTC. [Evidence records](docs/evidence/public/upgrade/README.md) retain the event IDs, hashed canary IDs, and incident joins.

## Proven

- Word opened a generated local DOCX and retrieved its public Azure callback. The same event reached Container Apps, Table Storage, Log Analytics, and High Sentinel incident 17.
- Six cloud callbacks produced six durable events and six structured SIEM rows. Two non-scanner first hits produced High incidents; one scanner first hit produced a Medium incident.
- Three repeat callbacks retained their classification and repeat counts, suppressed notification, reached Log Analytics, and produced no additional analytic alerts in the observed run.
- All 11 KQL files executed against the deployed workspace. Receiver health returned 200; management routes, docs, and OpenAPI returned 404.
- Local SMTP accepted one message after two callbacks while both events persisted. Failure regressions retained events and continued the independent delivery path.

## Not proven

Cloud SMTP, Protected View, downloaded attachments, another endpoint, mobile viewers, outage recovery, and sustained production load were not exercised. The run does not establish exactly-once delivery or distributed atomic suppression. Entra, Defender/EDR, SharePoint, Purview DLP, and network-log correlation remain future integrations.

The original local Word and controlled Azure demonstrations remain separate historical runs. The continuous proof belongs to this release.

## Sentinel

The [event contract](SENTINEL.md#event-contract) carries UTC time, UUID event ID, event type, hashed canary ID, artifact, observed IP and UA, classification, severity, scanner/duplicate/first-hit flags, repeat count, activation state at receipt, reason, recommended action, alert status, and receiver version. It excludes raw callback tokens.

| Scenario | Stored / ingested | Notifications | Incidents |
| --- | --- | --- | --- |
| Controlled non-scanner | 3 / 3 | First sent; two suppressed | 18, High |
| Controlled scanner | 2 / 2 | First sent; repeat suppressed | 16, Medium |
| Word cloud request | 1 / 1 | Sent | 17, High |

Two analytics filter eligible first hits by receiver classification. Repeats remain queryable. Rules run every five minutes with a one-hour event horizon and five-minute ingestion slice; incidents group by canary for one hour. This bounds duplicate incidents without claiming permanent or exact correlation. Grouping was inspected in deployed configuration; grouping of later fresh first-hit windows was not separately demonstrated.

## Azure

Built and deployed receiver 0.2.2 to the existing Container App. The deployed Direct DCR endpoint accepted all six release events. Table and SIEM rows matched by `EventId`. Sentinel custom details linked those events to alert IDs; the incident alerts API confirmed the three incident associations.

The Word event was generated by Word opening the document, not by a controlled request to that token. [The open record and cropped capture](docs/evidence/public/upgrade/README.md#word-to-sentinel) accompany the matching records.

## Security

Gitleaks 8.30.1 passed the full reachable Git history with redaction enabled. Public evidence uses allowlisted fields; source IPs, raw tokens, Azure account/resource identifiers, emails, and private paths are omitted. The Word capture excludes account controls and the pointer. Private evidence, databases, logs, generated decoys, environment files, and deployment responses are ignored.

The deployed receiver requires HTTPS and disables management/OpenAPI routes. Storage shared keys and ACR admin access are disabled. Its managed identity retains three roles: registry-scoped `AcrPull`, storage-account-scoped `Storage Table Data Contributor`, and DCR-scoped `Monitoring Metrics Publisher`. Table scope remains at the dedicated account because runtime initializes two tables. No runtime role was broadened.

Uvicorn access logging and proxy-header interpretation are disabled. Recent receiver console logs contained none of the release callback tokens. Upstream proxy, endpoint, and document-processing systems can still observe callback URLs; this check does not prove absence from every platform log. Forwarded-header trust remains disabled, so observed source addresses can represent ingress peers.

Temporary test tokens were revoked and the table-scoped operator role was removed after evidence collection. The event records and deployed resources were retained. [Cleanup record](docs/evidence/public/upgrade/cleanup.json).

## Limitations

A callback proves retrieval, not exfiltration or identity. NAT, VPN, proxies, scanners, and security gateways can obscure origin. External-content restrictions and offline opening can prevent a callback. Attribution requires endpoint, identity, DLP, and file-audit correlation. This complements DLP, access controls, encryption, EDR, and SIEM monitoring.

Suppression is a best-effort rolling window keyed by canary and UA. UA changes and concurrent visibility can create extra first hits; matching clients can share suppression. Delivery is synchronous without retries, and records are mutable. Resources remain deployed and no cost measurement was taken. [Full operational limits](LIMITATIONS.md).

## Recommendation

**PORTFOLIO_READY** for the documented scope. The deployed evidence demonstrates severity-aware detection engineering and one continuous Word-to-Sentinel path; it is not a claim of production readiness or universal viewer coverage.
